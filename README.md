# LINE Linux Helper

Unofficial community setup helper for running the **official Windows edition of LINE** on Linux through Wine.

> [!IMPORTANT]
> **This is not an official LINE installer.** This project is not affiliated with, endorsed by, or supported by LY Corporation or LINE.
>
> **No LINE binary is bundled in this repository.** The helper does not decode, decompile, reverse-engineer, patch, mirror, or redistribute LINE. During setup it downloads LINE's official Windows bootstrap installer **directly from LINE's CDN** and lets LINE's own installer install/update the application.

Thai documentation: [docs/README.th.md](docs/README.th.md)

## One-command install

Open a terminal in your Linux desktop session and run:

```bash
curl -fsSL https://raw.githubusercontent.com/Namnarak/line-linux-helper/main/bootstrap.sh | bash
```

That single command automatically performs the supported setup flow:

1. Detect the Linux distribution and CPU architecture.
2. Install required host dependencies for supported distro families.
3. Download the pinned Kron4ek Wine Proton runner.
4. Verify the runner SHA-256 before using it.
5. Create a dedicated 64-bit Wine prefix for LINE.
6. Configure Thai/CJK fonts and the compatibility signing profile.
7. Download `LineInst.exe` directly from LINE's official CDN.
8. Run LINE's own installer.
9. Create the desktop launcher.
10. Run a post-install health check.
11. Launch LINE automatically.

To install everything but skip the final automatic launch:

```bash
curl -fsSL https://raw.githubusercontent.com/Namnarak/line-linux-helper/main/bootstrap.sh | bash -s -- --no-launch
```

If you prefer to review the source before running it:

```bash
git clone https://github.com/Namnarak/line-linux-helper.git
cd line-linux-helper
./install.sh
```

## Why does this exist?

Recent LINE Desktop builds can reject Wine system DLLs with an error such as:

```text
Security verification failed.
File: C:\windows\system32\CRYPT32.dll
Reason: NO_SIGNATURE
```

`line-linux-helper` automates a community compatibility workaround in an **isolated Wine prefix**. The certificate generated by this project is self-signed on the user's machine and is **not issued by Microsoft**. See [SECURITY.md](SECURITY.md) before using the project.

## After installation

The installer now performs the initial health check and launch automatically. These commands remain available for normal maintenance:

```bash
line-linux launch
line-linux doctor
line-linux status
line-linux repair
line-linux repair --fonts
line-linux update
```

To remove the isolated prefix and helper:

```bash
line-linux uninstall
```

## Supported distributions

Automatic dependency installation currently targets these major families:

| Family | Examples | Status |
| --- | --- | --- |
| Arch | Arch Linux, CachyOS, Manjaro, EndeavourOS | Tested path |
| Debian/Ubuntu | Debian, Ubuntu, Linux Mint, Pop!_OS | Supported installer path |
| Fedora | Fedora, Nobara | Supported installer path |
| openSUSE | Tumbleweed, Leap | Supported installer path |
| Other | Any x86_64 distro with the required dependencies | `--no-packages` / manual deps |

Immutable/OSTree systems are detected and the helper intentionally does **not** mutate the host package database automatically. Install dependencies using the distro-supported method and run:

```bash
./install.sh --no-packages
```

NixOS, Alpine/musl and non-x86_64 systems are not currently claimed as supported.

## Current compatibility profile

The project intentionally pins the Wine runner instead of blindly tracking latest:

```text
Runner: Kron4ek Wine Proton 11.0-1 (amd64)
SHA256: 270dcbc3fdea9a19f1b60caed99fd8040639fb4626c69d424d0efdb12eb67b9f
LINE source: https://desktop.line-scdn.net/win/new/LineInst.exe
```

LINE itself is **not pinned or hosted by this repository**. `LineInst.exe` is LINE's official bootstrapper, so LINE's own infrastructure decides which current LINE build is installed.

## What the project does *not* do

- It does **not** provide a Linux port of LINE.
- It does **not** contain or redistribute LINE installers, EXEs, DLLs, assets, or source code.
- It does **not** decode/decompile/reverse-engineer LINE.
- It does **not** patch `LINE.exe` or its bundled DLLs.
- It does **not** install Wine DLL modifications globally.
- It does **not** claim the local compatibility certificate was issued by Microsoft.
- It does **not** guarantee calling/video/notification features unsupported by Wine will work forever.

## Font rendering

The helper also fixes common Wine font-rendering problems seen in LINE:

- installs the distro Noto Sans / Noto Sans Thai family when available,
- installs CJK fallback through Winetricks,
- enables RGB subpixel smoothing (gamma 1400),
- pins the Wine DPI profile to 96 DPI, and
- maps missing Windows UI families such as Segoe UI, Tahoma and Leelawadee UI to Noto fallbacks.

Repeated `repair` runs are incremental: unchanged Wine DLLs and an already-installed CJK profile are skipped.

No font files are stored in this repository. Host fonts come from the Linux distribution and CJK fallback is retrieved by Winetricks. Run `line-linux repair --fonts` after changing the Wine runner or if text becomes thin, jagged, or has poor Thai fallback.

## Security model

Only Wine DLLs inside the dedicated LINE prefix are signed. The signing key is generated locally with mode `0600` and stays under:

```text
~/.local/share/line-linux-helper/signing/
```

The helper never uploads the key or certificate.

The certificate subject uses Windows-like compatibility metadata because that is part of the current workaround. **The certificate remains self-signed.** This is a compatibility bypass of LINE's current system-DLL signature check inside a Wine prefix, not a Microsoft trust certificate.

Read [SECURITY.md](SECURITY.md) for the full threat model.

## Troubleshooting

Run:

```bash
line-linux doctor
```

If a Wine/runner update replaces DLLs and `NO_SIGNATURE` returns:

```bash
line-linux repair
```

If LINE itself needs to be re-fetched from the official CDN:

```bash
line-linux update
```

More details: [docs/troubleshooting.md](docs/troubleshooting.md)
